# 기획서 — 김보미 포트폴리오 v2.1 "Film & Stage" (재작성)

> 기준일: 2026.09.05 · 포지션: Frontend Developer
> **개정 핵심: WebGL/R3F 3D 씬 전면 제거.** 히어로는 실사 렌더 영상(스크롤 스크럽), 표지는 고화질 시안 이미지의 마우스 패럴랙스, 본문은 GSAP(ScrollTrigger) + motion 기반 인터랙티브 HTML로 전환한다.

---

## 1. 한 줄 컨셉

**"검은 문이 열리면 필름이 돌고, 필름이 끝나면 하얀 무대 위 표지가 남는다."**

- CH1 히어로: 검은 포털(문) → 스크롤로 문이 열리면 **한 컷짜리 3D 피규어 영상**이 스크롤에 맞춰 재생된다(스크롤 = 재생 헤드). 스크럽이 불가능한 환경은 일반 재생으로 폴백.
- CH2 랜딩(표지): 영상이 끝나면 화이트 지면 위에 **landing 시안(웅크린 피규어 컷)**이 카드로 놓인다. 마우스 위치에 따라 **그림자·뒤 볼륨·하이라이트·우측 KIM BOMI 타이포가 각각 다른 깊이**로 움직이는 2.5D 패럴랙스. 섹션은 pin 고정, 스크롤하면 아래로 흘려보낸다.
- CH3 이후: 3D 캐릭터/전시물 없음. **GSAP ScrollTrigger + motion**으로 만드는 타이포 중심 인터랙티브 섹션(가로 스크롤 갤러리, 리빌, 지면 반전).
- 흑백 반전 리듬 유지: **검정(필름) → 흰색(표지·본문) → 검정(클로즈)**.

## 4. 섹션 플로우

3D 키프레임 테이블·800vh 유령 트랙은 폐기한다. 각 섹션은 **일반 문서 흐름**에 놓이고, 핀·스크럽이 필요한 곳만 GSAP ScrollTrigger가 담당한다.

### CH1+CH2. HERO — 문 → 필름 → 풀블리드 표지 (단일 핀 `+=450%`) ★ 2026.09.05 개정

핀을 두 번 나누면 교대 지점에서 화면이 튄다 — **문 개폐·영상 스크럽·랜딩 리빌을 하나의 핀 타임라인**으로 묶어 끊김 없이 연결한다. 영상 마지막 프레임과 landing 시안이 같은 피규어·같은 검은 무대라 크로스페이드가 이음새 없이 이어진다.

| 로컬 진행도 | 요소 | 동작 |
|------|------|------|
| 0.00–0.14 | 문(패널·워드마크·도트) | 스크롤 스크럽으로 열림 — 역스크롤 시 다시 닫힘 |
| 0.10–0.66 | **영상** (`public/video/hero.mp4`) | `video.currentTime` 스크럽 — 스크롤이 곧 재생 헤드. duration은 lazily 읽어 핀 생성이 메타데이터를 기다리지 않게 한다 |
| 0.66–0.76 | 크로스페이드 | 영상 → **풀블리드 landing 시안** (autoAlpha + 스케일 1.14→1.02 정착) |
| 0.76–0.90 | 타이포 리빌 | 이미지 위로 네임 스택·플로팅 라벨 stagger 리빌 |
| 0.90–1.00 | 홀드 | 마우스 패럴랙스 무대 → 핀 릴리스, 자연 스크롤 아웃 |

**랜딩(표지) — 이미지 전체화면 + 텍스트 오버레이.** 포인터 패럴랙스는 깊이가 서로 다른 5개 레이어 (`--mx`/`--my`, usePointer lerp — zustand 홈 스타일):

| 레이어 | 마우스 반응 |
|--------|------------|
| 사진 (scale 1.06 여유) | 역방향 −16px |
| 하이라이트(시인) | 마우스 추적 radial |
| 타이포 블록 (우측) | 순방향 +26px |
| KIM BOMI 네임 | 타이포 블록 위에 +14px 누적 (한 겹 더 깊게) |
| 플로팅 라벨 (FIG.01 · SCROLL · ONE CONTINUOUS SHOT) | 최대 이동 ±38px |

텍스트 스택 (이미지 위, 밝은 잉크):

```
FRONTEND / KIM BOMI. / 프론트엔드 개발자 김보미
Building interfaces that respond like they're alive.
DEVELOPER · SEOUL · 2026
```

- **폴백(auto)**: `prefers-reduced-motion`·영상 오류 시 — 문 열린 상태 + 영상 1회 일반 재생, `ended` 이벤트에 랜딩 페이드 인. 사용자 요구사항: "안 되면 그냥 일반 재생".
- 스크럽 품질을 위해 영상은 **전체 키프레임(all-intra) 재인코딩본** 사용 (ASSET-PIPELINE.md).
- 화이트 아웃은 폐기 — 히어로는 다크로 끝나고, CH3 화이트 갤러리가 위로 스크롤 인하며 대비 컷을 만든다.

### CH3. WORK — 가로 스크롤 갤러리 `pin + containerAnimation`

3D 전시물 대신 **핀 고정 가로 스크롤**: 세로 스크롤이 대형 타이포 패널 3장(TCC · SITES · ALLEO)을 왼쪽으로 밀어낸다 (GSAP containerAnimation, `ease: none`).

- 패널: 화이트 지면 위 **검은 패널** — 프로젝트명(Syne 대형), 한 줄 요약, 결과 숫자 1개, 스택 라벨.
- 인터랙션: 호버 시 motion 스프링 틸트/부상 + 라벨 강조. 클릭 → 블랙 페이드 → `/work/[slug]`.
- 모바일: 핀·가로 스크롤 유지(터치 세로 스크롤로 동일 구동), 호버 제거.

### CH4. METHOD & ROSTER & DATES — 호흡 구간

콘텐츠는 v2 그대로(일하는 방식 스테이트먼트 + 로스터 5행 + 데이츠 4행). 리빌은 IntersectionObserver 대신 **GSAP ScrollTrigger 1회성 리빌**(y+fade, stagger)로 통일.

### CH5. JOURNAL — 기록

콘텐츠 v2 그대로. 헤드라인은 스크럽 클립 리빌(글자 마스크 위로), 리스트는 stagger 리빌.

- CH5 말미~CH6 진입에서 **지면 반전(흰→검)**: ScrollTrigger가 `body` 클래스 토글, CSS 변수 전환 0.6s.
- 콘텐츠: 메일·GitHub·Resume 필 버튼 + 푸터 + 크롭 워드마크 `BOMI.`(하단 크롭 유지). 캐릭터 클릭 리액션 카피는 삭제(3D 제거).

## 7. 기술 스택 개정

| 제거 | 추가 | 유지 |
|------|------|------|
| three · @react-three/fiber · @react-three/drei · @types/three | **gsap + @gsap/react** (ScrollTrigger 핀·스크럽) | Vite · React 19 · TS |
| zustand (progress·pointer 스토어 — CSS 변수·ScrollTrigger로 대체) | **motion** (호버·마이크로 인터랙션) | lenis (스무스 스크롤, ScrollTrigger와 ticker 동기화) |
| keyframes.ts 시네마 테이블 | | react-router-dom 7 |

- Lenis ↔ ScrollTrigger 연동: `lenis.on('scroll', ScrollTrigger.update)` + `gsap.ticker`가 `lenis.raf` 구동, `lagSmoothing(0)`.
- 스크롤 바인딩은 전부 scrub(역재생 가능), 텍스트 리빌은 1회성 — v2 모션 규칙 계승.

## 8. 모션 규칙 (전역)

| 규칙 | 내용 |
|------|------|
| 스크롤 바인딩 | 문·필름·화이트아웃·워드마크 패럴랙스·지면 반전 — scrub, 역스크롤 시 되감김 |

| 영상 실패 | poster(landing 시안) 정지 이미지로 폴백 |
| 모바일 | 스크럽·핀 유지, 호버 비트만 제거. 영상은 저해상 인코딩본 |

## 9. 성공 기준

- 첫 5초: 문이 열리고 스크롤에 필름이 감긴다 — "스크롤을 계속하고 싶은" 감각.
- CH2 표지가 스크린샷 한 장으로 공유 가능할 것 (시안 + KIM BOMI 타이포).
- 스크롤을 올리면 필름이 되감기고 문이 다시 닫힌다.
- 60fps 근접 — 3D 제거로 v2 대비 성능 여유 확보. `/work/*` 읽기 밀도 유지.
